# 架构和兼容边界

## 普通会话路径

Web 面板使用宿主的 `commands.execute` 调用 `/gene`，不另建聊天接口。应用配置创建 version 4、`mode:preferences`、`taskId:null` 的记录，写入原生 session record，由投影恢复。再次应用要求 Agent 空闲且 revision 匹配。

普通偏好不固定 effort、不接管调用预算，也不运行内置任务验证器。它通过系统提示中的具体偏好影响模型，并在原生工具续步时提供相关执行提示。停用后不继续提供 Gene 偏好。

状态持续到被替换或停用；同会话恢复自己的配置。普通会话分叉继承偏好，重新建立 run 身份和执行记录，不继承父会话已验证某个产物的结论。

## 工具集成

- `gene_tools_inspect`：只读当前 Agent 可见的工具注册表、schema 或执行记录，不开放隐藏工具或代为执行操作。
- `geneEditingTools`：消费最终 `tool/call`、`tool/result` 和嵌套 PTC 事件，保留身份、状态、摘要哈希及来源。
- `agent/pre-step`：只对可识别的新事件追加短提示；普通成功保持安静，没有原生续步时不制造新步骤，终止工具不会因此继续执行。
- `tool-feedback.mjs`：首次失败关联 RIG/DEP/SKE，重复失败关联 EXP/CRE/DEP/ABS/FOC，重复结果关联 FOC，恢复关联 RIG/SYN，声明版本变化关联 RIG/ABS/SYN。低档不追加该项提示，中高档给出相应强度的事件指引；八项常驻偏好继续生效。
- 宿主已给重复调用提醒时，抑制重复 FOC 提示；只有实际接纳的反馈才确认事件键并推进 acknowledgement。旧版本无事件键的反馈记录仍可读取。
- PTC 内部结果继续记录并可查询，续步提示由最终外层结果触发，不把外层已处理的内部失败当作新的修复任务。

最多保留128条近期观察/反馈、512个已提示事件键；去重以这些保留记录为范围，事件键淘汰后可能再次提示。每次续步最多三条事件说明；不要求模型执行额外步骤。以上是元数据/提示保留上限，不是模型请求上限。新用户消息清理工作观察与事件键，累计计数保留。权限、审批、调度、重试、取消和工具结果保持宿主语义。

相同操作按工具名、调用层级和参数哈希匹配。重复结果要求结果哈希也相同；变化的 stdout、图片或任意文本不自动构成冲突。内容版本变化仅依据现有显式契约的版本字段，并要求同一操作；不把版本变化当验证通过。未声明的业务状态仍保持 unknown。

当前显式业务适配主要针对 `ops_batch` / `ops_result` 的部分契约，其他工具保持 `business:unknown`。内容哈希是来源标识，不等于独立验证；页面完整不代表业务执行成功。原始工具结果仍由 Harness 交给模型。

## 显式验证兼容路径

`/gene {"op":"start",...}` 及 `shared/src/v4/verifiers` 保留历史实验工作流，包括受限 QuickJS 验证器。它们需要显式选择，普通三档面板只调用 `apply`。旧状态迁移和账本保持兼容，不把旧预算规则施加给新的普通偏好。

`controlled.patch.yml` 用于隔离实验，会关闭若干辅助模型调用、默认预设和重试等功能。`npm run profile -- --run` 创建 `.dsh-home/profiles/gene`，端口18478；这是受控开发环境，不是个人 profile 的替换配置。`npm run smoke:web` 使用本地 fixture，动态端口启动后停止测试宿主。

## 数据和生命周期

Gene 不导出私人思考，也不复制完整工具参数/输出到自己的元数据投影。Harness 原始日志和回放可能包含这些内容，插件不会替宿主清洗日志。不要把个人日志、profile 或认证链接作为发布附件。

当前兼容固定在 rc.3。Host 卸载/取消有回归测试；Web 在禁用插件后可能保留旧按钮/样式，热卸载与冷启动移除尚未完整验证。安装更新后重启目标服务并刷新页面。插件不可用时客户端清理可操作状态，旧按钮不能绕过已禁用的 Host。
