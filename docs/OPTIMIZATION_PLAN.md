# 0.6.3 优化计划与验收

这次针对外部评审已确认的问题实施：独立仓库遗漏验证器专项测试；工具续步重复追加固定 Gene 指引。目标是减少干扰，让偏好在合适的时机参与模型决策。人的创作取向和掌控感仍是体验目标。

## 实施顺序

1. **补齐测试**：迁移原有16项验证器/沙箱测试到独立仓库，调整为测试随安装包发布的运行文件。覆盖能力隔离、序列化篡改、资源中断和取消。
2. **按事件反馈**：保留系统提示中的八项语义偏好；普通成功结果不重复追加指引。仅依据实际执行元数据识别首次失败、相同操作的重复失败、重复输入得到相同结果、失败后的恢复，以及同一操作声明的内容版本变化。不得靠 stdout 关键词推断业务成功或把内容变化叫作证据冲突。
3. **去重和边界**：相同事件只在宿主实际接纳后记为已提示；重载、分叉、新问题和重新应用配置遵循原有隔离。原生重复提醒已存在时不再追加同类聚焦提醒。取消、终止和已处理的嵌套失败不制造续步。每次最多三条事件提示，不规定模型必须执行任何操作。
4. **验证和交付**：运行真实 rc.3 原生循环的本地测试、完整测试、Web冷启动和安装包检查。离线重放两份已完成的创作记录，比较反馈数量与文字量，仅作为注入机制检查；不重放模型/工具，不宣称作品因此变好。更新中文说明、发布说明和版本。

## 验收标准

- 只有正常成功且没有相关新事件的长序列，不追加 Gene 工具消息。
- 失败、重复、恢复和声明版本变化能够触发相应偏好，并留下调用身份；未知业务状态保持 unknown。
- 已提示的相同事件不会在下一步、重载或压缩后再次刷屏；未被宿主接纳的提示不提前确认。
- 原始结果、权限、取消、并行、辅助请求和终止语义保持完整，插件不新增模型调用、不自动重试。
- 全部工程检查通过；报告明确区分机制变化、离线回放与真实行为证据。

## 后续阶段

本轮不同时改写三档语义，以便把反馈机制变化单独审阅。探索/创造、严谨/质疑的语义区分、组合体验和可选预设另行比较；不删除八项独立控制。真实开放任务的同题重复比较仍需保留自然波动与人的偏好，不使用工具数或统一质量分代替体验。

旧 `verified` 路径本轮保留兼容，并补回测试。拆成独立包、扩展业务结果契约和跨宿主版本支持应分别实施和验证。

## 实施结果

已完成上述代码与文档优化：

- 完整 `npm run check`：113项通过，其中包含补回的16项验证器/沙箱测试。新增用例覆盖普通成功保持安静、重复/恢复/版本变化、实际接纳后去重、取消优先、旧记录兼容，以及离线回放的正控制。
- 隔离的真实 rc.3 Web 冷启动、插件清单和客户端资源加载通过；未使用真实模型额度。
- 两份既有本地创作轨迹的离线回放：原103＋95条工具反馈共197,540个字符，新规则均不追加。这些轨迹的原生结果均标为调用成功、没有可识别的声明版本事件；不能从中推断内部命令没有错误，业务状态仍为 unknown。八项系统偏好保持不变。
- 回放采用已完成的调用轨迹，只计算新版会插入的提示；没有再次调用模型或执行工具。结果说明重复上下文减少，不说明新作品会更好，也不预言模型会保持原轨迹。
- 打包、独立安装和安装后冷启动的逐项核验记录随 GitHub Release 提供。

复核自己的独立会话记录时，可先构建，然后执行：

```sh
node scripts/replay-feedback.mjs report.json path/to/session.v4.jsonl.zstd
```

支持 JSONL 与逐帧 Zstandard 文件，当前限定未分叉的独立会话。脚本只读输入，输出匿名编号、来源哈希、配置与计数，不输出提示正文、模型思考或工具参数/结果。字符数不是 token 数或累计计费输入。
